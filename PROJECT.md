# PROJECT.md — datadiff

## Что это

`datadiff` — CLI-инструмент для **семантического diff** структурированных
данных (JSON, YAML, CSV, TOML, XML). Сравнивает не строки файлов, а дерево
данных: порядок ключей и форматирование игнорируются, массивы объектов
матчатся по ключевому полю, изменения выводятся как пути в данных
(`spec.replicas: 3 → 5`), а не номера строк.

## Источник идеи: запросы пользователей

Идея выросла из обсуждения на Hacker News:
[«Graphtage: A semantic diff utility for JSON, HTML, YAML, CSV, etc»](https://news.ycombinator.com/item?id=26280266)
(февраль 2021, 405 поинтов, 51 комментарий). Graphtage (Trail of Bits) —
ближайший аналог; тред показал живой спрос на такую утилиту и одновременно
собрал список претензий к существующему решению:

| # | Запрос / боль пользователей | Кто озвучил |
|---|---|---|
| R1 | **Скорость.** Graphtage неюзабельно медленный: 45 kB CSV → оценка ~150 часов; два k8s-пода → 5 мин 17 сек против 10 мс у наивного Go-скрипта. Древовидные diff-алгоритмы имеют сложность вплоть до O(N⁴) | acidbaseextract, jrockway, IshKebab, dan-robertson |
| R2 | **Матчинг массивов по ключу.** Наивный diff ломается при переупорядочивании массивов вроде `containers` или `env` в k8s-манифестах | bboreham |
| R3 | **Контекст в глубокой вложенности.** «Нелегко понять контекст diff'а в глубоко вложенном YAML/JSON» — нужны пути в данных | rmetzler |
| R4 | **Локальный инструмент.** Online-only — не вариант для проприетарных данных | pimlottc |
| R5 | **Читаемый вывод.** Юникод-диакритика Graphtage визуально шумная; «плюс и минус в начале цветной строки работают отлично» | jacobolus, colejohnson66 |
| R6 | **Примеры ввода/вывода в README** | jonnycomputer |
| R7 | **Diff двух файлов, а не кластера.** `kubectl diff` существует, но не сравнивает два локальных манифеста | kmarc |
| R8 | Люди собирают велосипеды `gron \| sort \| diff \| delta` — нужен один инструмент | rmetzler |
| R9 | Roadmap-запросы: **patch-утилита** (сгенерировать компактный diff и применить на другой стороне), интеграция с **git/vimdiff** | indeyets, ducktective |
| R10 | Мультиформатность: JSON/YAML/CSV и конвертация между ними | deknos, hermitcrab |

## Как решаем

Ключевое архитектурное решение — **отказ от оптимального tree-diff
(Levenshtein/графовые алгоритмы) в пользу предсказуемого структурного
матчинга**:

- Объекты матчатся по ключам (`BTreeMap` — порядок ключей не имеет значения
  по построению). Массивы — по индексу или по значению ключевого поля
  (`--key id`). Сложность ~O(n log n) вместо O(N⁴). → R1
- `--key <field>`: массивы объектов матчатся по значению поля;
  переупорядочивание — не изменение. → R2
- Изменения выводятся как data-paths: `spec.replicas`,
  `users[id=4217].email`. → R3
- Офлайн-бинарник, сеть не используется вообще. → R4
- Легенда `+ / - / ~ / =` с цветами, без диакритики. → R5
- README содержит реальные примеры вывода (k8s, CSV, JSON). → R6
- Diff именно двух локальных файлов; k8s-манифесты — пример в `examples/`. → R7
- JSON, YAML, CSV, TOML, XML парсятся в единое дерево `Value`. → R10 (частично)

Exit codes: `0` — нет различий, `1` — есть различия, `2` — ошибка
(файл/формат). Это публичный контракт для использования в CI-гейтах.

## Архитектура

```
файл ──parse──▶ Value tree ──diff──▶ Vec<Change> ──render──▶ stdout
       (parse.rs)  (value.rs)  (diff.rs)            (output.rs)
```

- `src/value.rs` — внутреннее дерево `Value` (Null/Bool/Number/String/Array/Object),
  унификация чисел (`1 == 1.0`), конвертация через `serde_json` как общий
  интермедиат для всех форматов
- `src/parse.rs` — автодетект формата по расширению + парсеры 5 форматов;
  CSV → массив объектов (заголовок = ключи), числа авто-типизируются;
  XML → атрибуты как `@name`, текст элемента как `$text` (маппинг quick-xml)
- `src/diff.rs` — рекурсивный diff деревьев; объекты по ключам, массивы по
  индексу или по `--key` (fallback на индекс при дублях ключа / не-объектах)
- `src/patch.rs` — применение JSON-патча (`datadiff patch`): парсер путей
  (`users[id=4217].email`) + set/remove по дереву; нерешаемый путь — ошибка
- `src/write.rs` — сериализация дерева обратно в формат (`datadiff convert`):
  JSON/YAML/TOML/CSV; TOML требует объект в корне, CSV — массив плоских
  объектов, запись XML не поддерживается
- `src/policy.rs` — матчинг путей для `--fail-on` (точное совпадение,
  префикс по сегментам, `*` внутри сегмента)
- `src/output.rs` — цветной вывод `~/+/-/=` + итоговая сводка; JSON-вывод
  (`--output json`) для машинной обработки
- `src/main.rs` — CLI (clap, подкоманды `patch` и `convert`), оркестрация,
  exit codes
- `tests/cli_tests.rs` — интеграционные тесты через собранный бинарник

## Стек

- Rust 2021
- clap 4 (derive + `env`) — CLI и маппинг переменных окружения
- serde / serde_json — общая модель данных
- serde_yml, toml, csv, quick-xml — парсеры форматов
- anyhow — ошибки с контекстом
- colored — цветной вывод
- dotenvy — конфигурация через `.env`
- cargo test — интеграционные тесты
- GitHub Actions — CI на ubuntu / windows / macos

## Конфигурация

Через `.env` в рабочей директории (см. `.env.example`). Приоритет:
CLI-флаг > `.env` > дефолт.

| Переменная | Аналог флага |
|---|---|
| `DATADIFF_KEY` | `--key` |
| `DATADIFF_FORMAT` | `--format` |
| `DATADIFF_SHOW_UNCHANGED` | `--show-unchanged` |
| `DATADIFF_NO_COLOR` | `--no-color` |
| `DATADIFF_OUTPUT` | `--output` |
| `DATADIFF_EXIT_ZERO` | `--exit-zero` |
| `DATADIFF_FAIL_ON` | `--fail-on` |

## Статус реализации (честно)

Ядро R1–R8 написано; из R9 реализованы `--output json`, `datadiff patch` и
git diff-драйвер (`--exit-zero`); R10 закрыт целиком (XML + конвертация);
добавлены risk policies для CI (`--fail-on`) и чтение одной из сторон
из stdin (`-` вместо файла).

| Требование | Статус |
|---|---|
| R1 скорость | Дизайн ~линейный, без графовых алгоритмов |
| R2 `--key` | Реализовано + тесты |
| R3 data-paths | Реализовано |
| R4 офлайн | Да |
| R5 вывод `+/-/~/=` | Реализовано |
| R6 примеры в README | Да |
| R7 diff двух файлов | Да + examples |
| R8 замена gron-велосипедам | Следствие R1–R7 |
| R9 patch-утилита, git/vimdiff | `--output json` + `datadiff patch` + git diff-драйвер — да; git difftool / vim — рецепт в README |
| R10 форматы | JSON/YAML/CSV/TOML/XML + конвертация (`datadiff convert`) — да |
